# Xero Invoice/Bill on Claims + Audit Pack

`xero_invoices_bills` carries cached_pdf_object_key, last_fetched_at, deep_link_url, current_xero_status, is_stale, void_date. PDFs are pulled via `getInvoiceAsPdf` and stored on R2 under `xero_pdfs/<invoiceId>.pdf`. The webhook handler (INVOICE.UPDATE/CREATE) refreshes the cache; DELETE/VOID flips `is_stale=true` while preserving the cached PDF for audit. The 15-min webhook fallback scheduler reuses the same handler so cache refresh is automatic. `XeroSchedulerService.onApplicationBootstrap()` runs a throttled (~55/min) backfill so legacy rows get a cached PDF. Frontend `XeroIntegration` expander in `AddUpdateClaims.tsx` shows invoice number, status, deep link and a Download Xero PDF button — the latter calls GraphQL `getXeroInvoicePdfDownloadToken` (5-min JWT) and then GET `/files/xeroPdf` with `Authorization: Bearer <token>`. Audit-pack ZIPs include the cached PDF in `<module>/Attachments/Xero-<reference|invoiceId>.pdf` and the per-claim Excel adds Xero Invoice #, Xero Status, Xero Link, and Xero PDF File (in-zip relative path) columns. Each affected folder also gets `Attachments/Xero-Invoices-Index.csv` + `.xlsx` (claim id, reference, date, contract/project, invoice #, type, status, stale flag, void date, deep link, in-zip PDF path, Attached/Missing) so reviewers can trace every Excel row to the matching PDF on disk — or to the live deep link when the cache is empty. Coverage: ClientPaymentClaim, SupplierSubConPaymentClaim, and SupplierSubConPaymentSchedule (schedule rows resolve their Xero metadata via `pd.payment_claim_id`). At export time `appendXeroPdfsToArchive` runs a best-effort, throttled (3-way concurrent, 8s per call, 90s total budget) on-demand cache backfill via `XeroInvoicesService.fetchAndCacheXeroPdf` for any Xero-linked rows missing `cached_pdf_object_key`; failures are logged but never abort the export. The trimmed `Xero-README.txt` now points at the index instead of repeating per-claim lines, and the master `Summary.xlsx` gains a per-affected-module marker line (one entry pushed into the existing `masterSummary` array, matching the AccountingRecords pattern) that names the index file path and the attached/missing PDF counts. The Xero PDF append runs **before** the per-module Excel buffer is created so the new "Xero PDF File" column is populated rather than blank.
