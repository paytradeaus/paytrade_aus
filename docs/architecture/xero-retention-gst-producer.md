# Xero Retention/GST Handling (Producer)

When PT pushes claims to Xero, retention and liability lines are constructed via `getRetentionLineSpec()` which sets an explicit `taxType` per line (looked up from the Xero account, 5-min cached) and only grosses up `retention_amount` to inc-GST when (a) the invoice's `lineAmountTypes` is Inclusive AND (b) the destination account's tax type is GST-applicable (excludes BASEXCLUDED/NONE/EXEMPT*/INPUTTAXED). For Exclusive invoices the line stays ex-GST. For NoTax invoices no taxType is set. This prevents over-grossing on BAS-Excluded retention accounts. `retention_amount` is stored ex-GST in PT and the share deducted from each bill_code line uses the ex-GST value (no `* 1.1`). Base bill/invoice line `unitAmount`, `totalLineAmount`, and retention share proration all key off the resolved `lineAmountTypes` (`isInclusiveLine`) rather than `claimDetails.is_gst_optional`, so Exclusive updates send ex-GST `unit_price` (preventing Xero from double-applying GST when the original invoice was Exclusive).
