# Xero Retention Auto Gross-Up Journals (Phase 3)

When `xero_integration_details.auto_gross_up_retention_journals=true` AND `simplified_retention_accounting=false` AND `retention_recording_mode='ex_gst'`, PayTrade posts a balanced 2-line POSTED Manual Journal in Xero for the GST portion of retention so the held/release ledgers reconcile to the gross retention figure. New entity `XeroRetentionJournals` (`xero_retention_journals` table, unique partial index on `manual_journal_id IS NOT NULL` for anti-echo). New service `XeroManualJournalService` exposes `isAutoGrossUpEnabled / resolveGstApplicability / postGrossUpJournal / voidGrossUpJournal / voidAllForClaim / findByManualJournalId / listJournalsForClaim`. **Smart tax-type resolution order**: (1) bill/invoice base line `taxType` → (2) Phase 2 `resolveContactGstStatus` helper (per-contact override → cached Xero org default → `company.is_gst_registered`) → (3) `unknown` (no MJ posted, sync log written). `kind='gross_up'` on Claim creation (DR Retention Payable / CR Retention Held = GST), `kind='gross_up_reversal'` on `cash_retention_type='Retention claim'` (opposite signs). **Wire points**: outbound `xero-invoices.service.ts` `createInvoiceOrBillInXero` (post create) / `editInvoicesOrBills` (void+recreate) / `deleteInvoicesOrBills` (`voidAllForClaim`); inbound `webhook.service.ts` `createClaimInPaytrade` post-success. All call sites are wrapped in try/catch — failures write a sync log and never block the underlying claim flow. **Anti-echo**: `webhook-queue-consumer.service.ts` dispatches `MANUALJOURNAL.CREATE/UPDATE` to `webhook.service.ts.handleManualJournalUpdate` which checks `findByManualJournalId` and drops self-echoes (sync log template 606). External MJs are no-op for now. **Sync log templates**: 600 (gross_up posted) / 601 (skipped) / 602 (failed) / 603 (reversal posted) / 604 (voided) / 605 (release reversal) / 606 (anti-echo). **Frontend**: `XeroIntegration.tsx` claim drawer expander adds a "Retention GST gross-up journals" table fed by GraphQL `getXeroRetentionJournalsForClaim` (newest first, shows kind/status/ex-GST/GST/tax-type/source/posted timestamp + error text on FAILED rows). Idempotent `XeroRetentionJournalsSchemaSeederModule` adds the column + table in production via `ALTER TABLE IF NOT EXISTS`/`CREATE TABLE IF NOT EXISTS`.
