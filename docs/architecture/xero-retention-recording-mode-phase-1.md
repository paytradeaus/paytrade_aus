# Xero Retention Recording Mode (Phase 1)

`xero_integration_details` carries `retention_recording_mode` enum (`ex_gst` default / `inc_gst`) and optional `retention_tax_type` text. `getRetentionLineSpec()` accepts both — when `inc_gst` AND the invoice is `Inclusive`, retention/liability/release lines are gross-upped (`* 1.1`) regardless of the destination Xero account's tax type, and `retention_tax_type` overrides the account-derived `taxType` on the line. The consumer split (xero-invoices.service.ts ~L2597 and webhook V-Step ~L2925 / D-Step ~L3730) honours the same mode: when `inc_gst` + Inclusive, `retentionUnitOnly` is derived from `unitAmount/1.1` and `retentionTaxOnly` from `unitAmount - unitAmount/1.1` instead of trusting the (often zero) per-line `taxAmount`. `adjustItemsWithRetention()` now recomputes per-line GST as `newUnitAmount × perLineRate` (rate = `item.taxAmount / unitAmount`, fallback to `invoice.totalTax / invoice.subTotal`, then `0.10`) so the restored bill_code line's GST always equals `unit_price × rate` (fixes the $1,493.78 vs $1,572.40 mismatch on a $15,724 unit price). The Add/Edit Claim form's `Unit price` header is labelled `Unit price (ex-GST)` with a tooltip clarifying the GST tickbox adds 10% on top.
