# Xero Contact GST Sync (Phase 2)

Two-way per-contact GST defaults between PT and Xero. New columns `client_suppliers_details.xero_sales_gst_setting` / `xero_purchases_gst_setting` (text, NULL = use org default), `company_details.is_gst_registered` (nullable bool, NULL = unknown), and `xero_integration_details.xero_org_country_code / xero_org_is_gst_registered / xero_org_sales_tax_basis / xero_org_default_sales_tax / xero_org_default_purchases_tax / xero_org_settings_synced_at` (cache of Xero org GST defaults). Idempotent `XeroContactGstSchemaSeederModule` adds the columns in production via `ALTER TABLE IF NOT EXISTS`.

- **Outbound (PT → Xero)**: All four contact-write paths in `xero-contacts.service.ts` (createContact ~L286, insertContactDetailsInPaytrade post-import update ~L765, editContact ~L1085, batch create ~L297) call `applyContactGstToXeroPayload(target, ptContact)` to copy `xero_sales_gst_setting` → `salesDefaultTaxType` and `xero_purchases_gst_setting` → `purchasesDefaultTaxType`. The sentinel value "Use organisation settings" and blank/null are skipped, leaving the Xero default untouched.
- **Inbound (Xero → PT)**: `webhook.service.ts` `handleContactCreateUpdate` ~L348 calls `persistContactGstFromXero(pt_contact_id, contact)` after every contact webhook. The batch import paths (syncAll/refreshContacts/autoCreateSingle) intentionally rely on the per-contact webhook fan-out plus the manual `backfillContactGstFromXero` mutation for one-time backfill, since `summaryOnly=true` Xero list calls strip the tax defaults.
- **Org defaults cache**: `XeroService.refreshOrgGstDefaults(company_id)` calls `getOrganisations`, derives `isGstRegistered` from `salesTaxBasis !== 'NONE'`, and writes the cache. Wired into the existing hourly `XeroSchedulerService.checkAndRunJobs` cron after `refreshTokenSet`, best-effort (errors are logged, never blocking).
- **`resolveContactGstStatus(contact, claimType, orgDefaults?, company?)` helper** (`back-end/src/api/common/integrations/xero/contacts/contact-gst-resolver.ts`) — pure function returning `{ taxType, source, resolved }`. Resolution order: per-contact override → cached Xero org default → `company.is_gst_registered` ('GST on Income/Expenses' if true, 'BAS Excluded' if false) → `{ taxType: null, source: 'unknown', resolved: false }`. Sales vs purchases path is keyed off `claimType === 'Receivable'`.
- **Alignment endpoints**: `backfillContactGstFromXero` and `backfillContactGstFromPaytrade` GraphQL mutations in `xero-contacts.resolver.ts` iterate over every mapped contact for the calling company and either pull or push the per-contact GST defaults; both return a JSON-stringified `{ scanned, updated|pushed, skipped, errors }` summary suitable for displaying in the Xero Settings widget.
- **Frontend**: `AddClientsAndSuppliers` form gains two optional dropdowns (sales/purchases GST tax type) sourced from `xeroGstTypeOptions` constant; "Use organisation settings (default)" maps to NULL. `BusinessProfile` adds an `is_gst_registered` checkbox under "Manage email preferences"; the value flows through `BusinessProfileContext` → `updateCompanyDetails` mutation. `UpdateCompanySignupInput` accepts `is_gst_registered`; `signup.service.ts` `updateCompanyDetails` ~L1124 persists it (only when explicitly provided, preserving NULL = unknown).
