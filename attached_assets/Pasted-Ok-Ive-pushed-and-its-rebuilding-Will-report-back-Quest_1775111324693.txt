Good question — let me trace through the code to verify exactly how claims with retention are handled in both directions.

Your thinking is close but not exactly right — here's what the code actually does:

For a $10,000 claim with 5% retention ($500):

The code creates 3 types of line items, but the structure is slightly different from what you described:

Work line items — The original line items with their unit amounts reduced by their proportional share of the retention. So the total of these lines adds up to $9,500. These get the normal tax treatment (GST via your configured invoice_tax_code or bill_tax_code).

"Retention Held" (positive) — A single line for $500 (or $550 if GST-inclusive, since the code multiplies by 1.1 when GST applies). This goes to the retention_payable_retained_code (for bills) or retention_receivable_retained_code (for invoices). No Tax / BAS Excluded treatment.

"Liability for defects" (negative) — A line for -$500. This goes to the liability_payable_code (for bills) or liability_receivable_code (for invoices). No Tax / BAS Excluded treatment.

So the net effect is that the invoice total in Xero equals $9,500 + tax (the retention lines cancel each other out: +$500 - $500 = $0), but the retention is properly tracked across the right Xero accounts.

For the reverse direction (Xero to PayTrade):

When syncing from Xero, PayTrade identifies retention claims by checking if any line items use the configured retention or liability account codes. It specifically:

Looks for lines mapped to retention_payable_retained_code / retention_receivable_retained_code → identifies it as a standard claim with retention held
Looks for lines mapped to retention_payable_release_code / retention_receivable_release_code → identifies it as a "Retention claim" (release)
Requires exactly 2 matching retention/liability lines — if one is missing, the import fails with a validation error
There's also a "Smart Contract Resolution" feature that matches the supplier, project, and total amount against existing contracts when a Xero invoice doesn't have a tracking category for the contract.
